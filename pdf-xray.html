PDF X-Ray

Drop a PDF in. It never leaves this tab — the same vendored pdf-lib this repo ships is doing the parsing, in your browser, from a local file. Shows exactly what our own editor sees: every font's real /BaseFont, whether its program is actually embedded, and the raw, decompressed content-stream operators for any page.

Drag a PDF here, or click to choose a file

Fonts — per page

"Embedded" means a real glyph program (FontFile/FontFile2/FontFile3) is packed inside this file. When it says no, the shapes you see on screen are on loan from whatever's installed on the viewing device — not from the file at all.

Images — per page

Every /XObject of /Subtype /Image the page paints, with its real compression /Filter — this is what actually decides whether a "photo" on the page is a JPEG, a raw/Flate pixel array (PNG-shaped), or a fax-style scan compressor (CCITTFaxDecode/JBIG2Decode, the two you'll see most on scanned government documents). A page with no rows here paints nothing but vector/text content.

Raw content stream

The literal recorded instructions for the page: BT/ET brackets a text object, Tf sets the font + size, Tm positions it, Tj/TJ paints the string. Decompressed straight off the bytes — this is what core/redact.js's own reader sees, byte for byte.
